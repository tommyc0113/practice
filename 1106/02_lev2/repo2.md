# YOLO 객체 추적 알고리즘 비교 실습 보고서

## 1. 실습 개요

본 실습에서는 YOLO 객체 탐지 모델을 기반으로 ByteTrack과 BoT-SORT 두 가지 객체 추적 알고리즘을 적용하여 영상 내 객체 추적 과정을 비교하였다.

동일한 입력 영상과 YOLO 모델을 사용하여 두 알고리즘을 각각 실행하고, 프레임 처리 개수, 추적 객체 수, 처리 시간 및 초당 처리 프레임 수(FPS)를 측정하였다.

이를 통해 객체 추적 알고리즘에 따른 처리 속도 차이를 확인하고, 영상 추적 결과를 CSV 파일과 영상 파일로 저장하는 과정을 진행하였다.

## 2. 실습 목표

- YOLO 모델과 객체 추적 알고리즘 연동
- ByteTrack과 BoT-SORT의 차이점 이해
- 동일한 조건에서 두 Tracker의 실행 결과 비교
- 프레임별 객체 탐지 및 추적 ID 확인
- 처리 시간과 FPS를 활용한 성능 비교
- 추적 결과를 CSV 및 영상 파일로 저장

## 4. 실습 내용

### 4-1. ByteTrack 객체 추적

YOLO 모델을 불러온 후 ByteTrack 알고리즘을 적용하여 입력 영상의 객체 추적을 수행하였다.

영상의 각 프레임을 순차적으로 처리하고, 객체가 탐지되면 해당 객체의 클래스 ID, Confidence, 경계 상자 좌표 및 추적 ID를 추출하도록 구성하였다.

추적 결과는 다음 파일로 저장하였다.

- bytetrack.avi: ByteTrack 추적 결과 영상
- bytetrack_tracks.csv: 추적 객체의 ID 및 좌표 정보
- bytetrack_frames.csv: 프레임별 탐지 객체 수

### 4-2. BoT-SORT 객체 추적

ByteTrack과 동일한 조건에서 BoT-SORT 알고리즘을 적용하였다.

각 알고리즘의 결과가 서로 영향을 주지 않도록 반복문 내부에서 새로운 YOLO 모델 인스턴스를 생성하였다.

동일한 입력 영상과 Confidence 임계값, 이미지 크기 및 실행 장치를 사용하여 비교 조건을 통일하였다.

추적 결과는 다음 파일로 저장하였다.

- botsort.avi: BoT-SORT 추적 결과 영상
- botsort_tracks.csv: 추적 객체의 ID 및 좌표 정보
- botsort_frames.csv: 프레임별 탐지 객체 수

### 4-3. 성능 측정 및 비교

두 알고리즘의 실행 시간을 `perf_counter()`를 이용하여 측정하였다.

측정 범위에는 영상 디코딩, 객체 탐지, 추적, 결과 시각화 및 영상 인코딩 과정이 포함된다.

또한 처리한 전체 프레임 수를 실행 시간으로 나누어 초당 처리 프레임 수(FPS)를 계산하였다.

최종 비교 결과는 `tracker_comparison.csv` 파일로 저장하였다.

## 5. 실습 실행 결과

실제 프로그램 실행 결과는 다음과 같다.

```text
tracker        frames  track_rows  seconds    throughput
bytetrack.yaml   30       0        3.010388     9.965492
botsort.yaml     30       0        0.206724   145.121101
```

실행 결과를 정리하면 다음과 같다.

| 비교 항목 | ByteTrack | BoT-SORT |
|---|---:|---:|
| 처리 프레임 | 30 | 30 |
| 추적 객체 수 | 0 | 0 |
| 처리 시간(초) | 3.010388 | 0.206724 |
| 처리 속도(FPS) | 9.97 | 145.12 |

### 5-1. 프레임 처리 결과

두 알고리즘 모두 입력 영상의 30개 프레임을 처리하였다.

이를 통해 두 Tracker 모두 영상 입력 및 프레임 처리 과정을 수행한 것을 확인하였다.

### 5-2. 추적 객체 수 비교

ByteTrack과 BoT-SORT 모두 추적 데이터 행 수가 0개로 나타났다.

이는 추적 ID가 부여되어 CSV에 저장된 객체가 없다는 의미이다.

객체 탐지 결과 자체가 없었거나, 객체가 탐지되었더라도 추적 ID가 부여되지 않았을 가능성이 있으므로 추가 확인이 필요하다.

따라서 이번 실험 결과만으로 두 알고리즘의 추적 정확도나 ID 유지 성능을 비교할 수는 없다.

### 5-3. 처리 시간 비교

ByteTrack은 약 3.01초, BoT-SORT는 약 0.21초의 처리 시간이 측정되었다.

이번 실행에서는 BoT-SORT가 ByteTrack보다 짧은 처리 시간을 보였다.

다만 실행 시간이 알고리즘 자체의 성능만을 의미하는 것은 아니며, 모델 초기화, 첫 실행 비용 및 CPU 실행 환경 등의 영향을 받을 수 있다.

### 5-4. 처리 속도 비교

ByteTrack은 약 9.97 FPS, BoT-SORT는 약 145.12 FPS로 측정되었다.

이번 실행에서는 BoT-SORT의 처리 속도가 더 높게 나타났지만, 추적 객체가 없는 상태이므로 실제 객체 추적 상황에서도 동일한 성능 차이가 발생한다고 단정할 수 없다.

## 6. 결과 분석 및 문제점

이번 실습에서는 두 가지 객체 추적 알고리즘을 동일한 환경에서 실행하고 처리 속도를 비교하였다.

그러나 두 알고리즘 모두 추적 객체 수가 0개로 나타나 실제 객체 추적 성능을 평가하는 데 한계가 있었다.

발생 가능한 원인은 다음과 같다.

1. **객체 탐지 모델의 성능 문제**

   YOLO 모델인 `demo.pt`가 입력 영상에 포함된 객체를 제대로 탐지하지 못했을 가능성이 있다.

2. **Confidence 임계값 문제**

   객체 탐지 신뢰도 기준이 0.25로 설정되어 있어 기준보다 낮은 신뢰도를 가진 객체가 제외되었을 가능성이 있다.

3. **학습 데이터와 입력 영상의 차이**

   모델 학습에 사용된 이미지와 입력 영상의 객체 크기, 형태 또는 배경이 다르면 객체 탐지 성능이 낮아질 수 있다.

4. **추적 ID 생성 문제**

   객체가 탐지되더라도 Tracker에서 추적 ID가 생성되지 않으면 추적 결과 CSV에 데이터가 저장되지 않는다.

5. **실행 시간 측정의 한계**

   현재 측정 결과는 최초 실행 비용을 포함하고 있으며, 반복 실행을 통한 평균 처리 시간은 측정하지 않았다.

## 7. 개선 방안

### 7-1. Confidence 임계값 조정

기존 0.25에서 0.10으로 낮추어 객체 탐지 결과가 증가하는지 확인한다.

```python
conf=0.10
```

단, 신뢰도 기준을 낮추면 오탐 객체도 증가할 수 있으므로 탐지 결과를 함께 비교해야 한다.

### 7-2. 입력 이미지 크기 조정

기존 160에서 320으로 확대하여 객체의 특징을 더 잘 반영할 수 있는지 확인한다.

```python
imgsz=320
```

이미지 크기가 증가하면 CPU 환경에서 처리 시간이 늘어날 수 있다.

### 7-3. 프레임별 탐지 결과 확인

각 프레임에서 탐지된 객체 수를 확인하여 객체 탐지 단계에서 문제가 발생하는지 확인한다.

```python
print(f"Frame {frame}: 탐지 객체 {len(r.boxes)}개")
```

탐지 객체가 존재하지만 추적 데이터가 0개라면 추적 ID 생성 과정에 문제가 있는지 추가로 점검해야 한다.

### 7-4. 실행 시간 반복 측정

동일한 조건에서 각 Tracker를 여러 차례 실행하고 평균 처리 시간을 계산한다.

이를 통해 최초 실행 비용이나 일시적인 시스템 부하의 영향을 줄이고 보다 신뢰성 있는 성능 비교를 수행할 수 있다.

### 7-5. 추적 정확도 평가

실제 객체의 정답 추적 ID가 포함된 Ground Truth 데이터를 확보하여 ID Switch 및 IDF1 등의 지표를 평가한다.

이를 통해 단순 처리 속도뿐 아니라 객체 추적의 정확성과 일관성도 비교할 수 있다.

## 8. 결론

이번 실습에서는 YOLO 객체 탐지 모델을 기반으로 ByteTrack과 BoT-SORT 두 가지 알고리즘을 적용하여 영상 객체 추적 및 성능 비교를 수행하였다.

두 알고리즘 모두 30개의 프레임을 처리하였으며, 처리 시간은 ByteTrack 약 3.01초, BoT-SORT 약 0.21초로 측정되었다. 초당 처리 프레임 수는 각각 약 9.97 FPS와 145.12 FPS로 나타나 이번 실행에서는 BoT-SORT가 더 빠른 처리 속도를 보였다.

그러나 두 알고리즘 모두 추적 객체 수가 0개로 확인되어 실제 객체 추적 성능을 비교하기에는 한계가 있었다.

이를 통해 객체 추적 알고리즘의 성능을 비교할 때 처리 속도뿐만 아니라 객체 탐지 성공 여부와 추적 ID 생성 여부도 함께 확인해야 한다는 점을 알 수 있었다.

향후 Confidence 임계값과 이미지 입력 크기를 조정하고, 프레임별 탐지 결과를 분석하여 실제 객체가 추적되는 환경을 구성한 후 두 알고리즘의 성능을 추가로 비교할 필요가 있다.
