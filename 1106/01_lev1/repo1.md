# YOLO 객체 탐지 및 ByteTrack 영상 추적 실습 보고서

## 1. 실습 개요

본 실습에서는 YOLO 객체 탐지 모델을 활용하여 이미지 내 객체를 탐지하고, ByteTrack 알고리즘을 적용하여 영상 속 객체를 프레임 단위로 추적하는 과정을 진행하였다.

이미지 탐지에서는 객체의 위치와 클래스, 신뢰도(Confidence)를 확인하고, 영상 추적에서는 동일한 객체에 추적 ID(Track ID)를 부여하여 프레임이 변경되어도 객체를 식별할 수 있는지 확인하였다.

## 2. 실습 목표

- YOLO 모델을 이용한 이미지 객체 탐지 수행
- 객체의 클래스와 위치 좌표, 신뢰도 확인
- ByteTrack 알고리즘을 이용한 영상 객체 추적
- 프레임별 탐지 결과와 추적 결과를 CSV 파일로 저장
- 실행 결과를 분석하고 모델의 한계 및 개선 방안 도출

## 3. 개발 환경

| 구분 | 내용 |

## 4. 실습 내용

### 4-1. YOLO 이미지 객체 탐지

학습된 YOLO 모델인 `demo.pt`를 불러온 후 검증 이미지 폴더를 대상으로 객체 탐지를 수행하였다.

탐지 과정에서 신뢰도 기준을 0.25로 설정하고, 이미지 크기는 160으로 지정하였다.

탐지 결과에서 다음 정보를 추출하였다.

- 이미지 파일명
- 객체 클래스 ID
- 객체 탐지 신뢰도
- 객체의 경계 상자 좌표(x1, y1, x2, y2)

탐지 결과는 `p07_predictions.csv` 파일로 저장하도록 구성하였다.

### 4-2. ByteTrack 영상 객체 추적

영상 파일 `demo.avi`를 입력 데이터로 사용하고 ByteTrack 알고리즘을 적용하였다.

영상의 각 프레임을 순차적으로 처리하면서 객체 탐지 결과를 확인하고, 추적 ID가 존재하는 객체에 대해 클래스 ID, 신뢰도, 경계 상자 좌표를 저장하였다.

또한 프레임별 탐지 객체 수를 기록하고 추적 결과가 표시된 영상을 `p07_tracked.avi` 파일로 저장하도록 구성하였다.

### 4-3. 결과 데이터 저장

실습 결과는 다음 세 가지 CSV 파일로 저장하도록 구성하였다.

| 파일명 | 저장 내용 |
|---|---|
| p07_predictions.csv | 이미지별 객체 탐지 결과 |
| p07_tracks.csv | 프레임별 객체 추적 ID 및 좌표 |
| p07_frames.csv | 프레임별 탐지 객체 수 |

## 5. 실습 실행 결과

실제 프로그램 실행 결과는 다음과 같다.

```text
입력 fps/size: 10.0 (160, 128)
처리 Frame: 30
추적 객체 수: 0
```

실행 결과를 분석하면 다음과 같다.

| 항목 | 결과 | 분석 |
|---|---:|---|
| 입력 FPS | 10.0 | 초당 10프레임의 영상 |
| 영상 크기 | 160 × 128 | 입력 영상의 해상도 |
| 처리 프레임 | 30 | 총 30개 프레임 처리 |
| 추적 객체 수 | 0 | 추적 ID가 부여된 객체가 없음 |

영상은 총 30프레임까지 정상적으로 처리되었으나, 최종 추적 결과에 저장된 객체 수는 0개로 확인되었다.

이는 영상 처리 자체는 진행되었지만, 객체 탐지 결과가 없었거나 탐지된 객체에 대해 추적 ID가 부여되지 않았을 가능성이 있음을 의미한다.

따라서 현재 결과만으로 ByteTrack이 정상적으로 객체를 추적했다고 판단하기는 어렵다.

## 6. 결과 분석 및 문제점

이번 실습에서는 YOLO 객체 탐지와 ByteTrack 영상 추적 과정을 연결하는 데 성공했지만, 실제 추적 객체가 0개로 출력되는 문제가 발생하였다.

가능한 원인은 다음과 같다.

1. **모델 탐지 성능 문제**  
   학습된 `demo.pt` 모델이 입력 영상에 포함된 객체를 충분히 탐지하지 못했을 가능성이 있다.

2. **Confidence 임계값 문제**  
   신뢰도 기준이 0.25로 설정되어 있어 해당 기준보다 낮은 신뢰도를 가진 탐지 결과가 제외되었을 가능성이 있다.

3. **입력 데이터와 학습 데이터의 차이**  
   학습 이미지와 실제 입력 영상의 객체 형태나 크기, 배경 등이 다를 경우 탐지 성능이 낮아질 수 있다.

## 7. 개선 방안

추적 객체가 0개로 출력되는 문제를 개선하기 위해 다음과 같은 방법을 적용할 수 있다.

### 7-1. Confidence 임계값 조정

기존 0.25에서 0.10으로 낮추어 탐지 대상이 증가하는지 확인한다.

```python
conf=0.10
```

단, 신뢰도 기준을 낮추면 실제 객체가 아닌 오탐 결과도 증가할 수 있으므로 결과를 비교해야 한다.

### 7-2. 이미지 입력 크기 조정

기존 이미지 크기 160에서 320으로 확대하여 객체의 특징을 더 잘 반영할 수 있는지 확인한다.

```python
imgsz=320
```

이미지 크기 확대는 CPU 환경에서 처리 시간이 증가할 수 있다.

### 7-3. 프레임별 탐지 결과 확인

각 프레임에서 탐지된 객체 수를 출력하여 객체 탐지 단계와 추적 단계 중 어느 부분에서 문제가 발생하는지 구분한다.

```python
print(f"Frame {frame}: 탐지 객체 {len(result.boxes)}개")
```

이를 통해 객체 탐지 결과가 없는 것인지, 탐지는 되었지만 추적 ID가 생성되지 않은 것인지 확인할 수 있다.

### 7-4. 학습 데이터 및 모델 점검

검증 이미지와 입력 영상의 객체 형태를 비교하고, 필요하면 학습 데이터를 추가하거나 모델을 재학습하여 탐지 성능을 개선한다.

## 8. 결론

이번 실습을 통해 YOLO 모델을 활용한 이미지 객체 탐지와 ByteTrack을 활용한 영상 객체 추적의 전체적인 처리 과정을 이해하였다.

YOLO는 이미지에서 객체의 위치와 클래스를 탐지하고, ByteTrack은 탐지 결과를 바탕으로 프레임 간 객체를 연결하여 추적 ID를 부여한다는 차이점을 확인하였다.

실행 결과 영상의 30개 프레임은 처리되었으나 추적 객체 수가 0개로 나타났다. 이를 통해 영상 처리 성공 여부와 객체 추적 성공 여부는 별도로 확인해야 한다는 점을 알 수 있었다.

향후 Confidence 임계값과 이미지 입력 크기를 조정하고, 프레임별 탐지 결과 및 학습 데이터를 점검하여 실제 객체 추적 성능을 개선할 필요가 있다.
